# Arabic style rules for the decision workbook (owner's instructions, 2026-10-28)

1. **No passive voice and no impersonal forms.** Banned: أُجِّل، يُحفظ، تُحسب، يُطبَّق، مُؤجَّل as a verb substitute, «يتم + مصدر», «تم + مصدر», «سيتم». Use:
   - first person plural for our side: نبني، نحفظ، نحسب، أجّلنا، نقترح
   - direct address for the company: اختاروا، حدّدوا، هل تريدون…؟
   - a named actor when someone else acts: الهيئة الشرعية تعتمد…، المدير المالي يوقّع…
2. **Short and to the point.** Limits:
   - summary ≤ 20 words
   - each rule ≤ 12 words; at most 10 rules per module
   - at most 4 deferred items, each ≤ 10 words
   - title ≤ 6 words; question ≤ 20 words
   - context: one sentence ≤ 22 words, with a number example only if it is essential
   - edge cases: at most 3, each ≤ 9 words
   - option label ≤ 9 words; consequence ≤ 12 words
   - recommendation reason ≤ 15 words
3. **English where Arabic is awkward or less known**, written in Latin letters inside the Arabic sentence: Edge cases, IBNR, SLA, KPI, PDF, QR, API, OTP, UAT, Quota Share, Excess of Loss (XoL), Stop Loss, Bordereau, KYC, PEP, AML, goAML, IFRS 17, AAOIFI, FAS 42, Metabase, Power BI, Excel, CSV, SMS, Stripe, PayPal, Moamalat, LYPAY, TypeScript, Odoo, AWS, Azure, Frankfurt, cash-up, pen test. Keep Arabic for takaful terms that are Arabic by origin (وكالة، مضاربة، قرض حسن، تبرع، فائض، صندوق المشتركين، صندوق المساهمين، الهيئة الشرعية).
4. Never write «حالات حدّية». The label is **Edge cases** (in English).
5. Keep every `id`, option `key`, `recommended`, `owner_ar`, `needed_by_day`, `priority` and `refs` exactly as they are. **Keep each option's meaning exactly as it is**: client answers already point to option keys.
6. Never use the letters "WP".
